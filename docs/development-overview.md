## 2. 总体结论

项目已经从两页最小示例发展为可复用的中文 Beamer 主题：五个标准主题文件各司其职，提供 Academic、Warm、Cool 三种视觉模式，支持常用学术内容，并有四份独立示例、统一构建脚本和尺寸微调接口。

**总纲 Phase 1～5 的主要交付项均已有实现。** 目前具备本机 Windows + XeLaTeX 的日常使用基础。仍没有跨平台实测、正式发行包与自动文献工具链；学校视觉素材继续仅在本地使用，不随 Git 源码分发。不能据此宣称项目已经完成公开发布或获得学校官方认可。

| 总纲目标 | 当前实际情况 | 判断与边界 |
| --- | --- | --- |
| 16:9、XeLaTeX、中文演示 | 四份示例均使用 `ctexbeamer` 与 `aspectratio=169` | 本机可用；其他比例未系统验证 |
| 统一 HUAS 视觉语言 | 暖红强调、黑体标题、宋体正文、可选校徽和用户建筑素材；增加参考教学 PDF 的蓝色模式 | 属于项目推导设计，不是学校官方 VI |

## 3. Phase 1：建立主题核心

**总纲要求：** 标准五文件、颜色令牌、字体层级、正文标题、页脚页码、Logo 加载器和基础选项。

**实际实现：** `beamerthemeHUAS.sty` 作为入口，另四个 `beamer*themeHUAS.sty` 分别管理颜色、字体、内层与外层。`theme/huas-assets.tex` 提供校徽加载。早期 `footer/nofooter`、`logo/nologo` 选项目前仍保留。研究素材、参考仓库和编译产物归入对应目录并被 Git 忽略；总纲涉及的参考代码共下载八个本地仓库。

**当时验证：** 阶段记录为两页示例连续两遍编译；另验证校徽、关闭页脚和缺失图片提示。

**不足及后续处理：** 当时只有默认封面，中文字体依赖平台默认，许可证未确定。封面由 Phase 2 补齐；配置由 Phase 3 统一；字体由 Phase 5 调整；许可准备单独完成。推导色 `A34A42` 没有官方 VI 依据，这个边界至今成立。

**评价：** 核心架构目标达到，为后续模块增加留下了清晰位置。

## 4. Phase 2：建立核心视觉页面

**总纲要求：** 封面、章节、普通内容、双栏图片、结束页；校名、校徽、校训和适度的建筑辅助图形。

**实际实现：** 五类页面及身份文字已实现。普通双栏沿用 Beamer `columns`；完整页面目前使用 `\HUASmaketitle`、`\HUASsectionframe`、`\HUASclosingframe`。缺校徽时保留校名文字，正文缺图时可显示占位框。按用户明确指定，将版权持有人与 Current Maintainer 更新为 `bsxiaocai`。

**当时验证：** 五页示例逐步编译与渲染；不带研究素材的独立目录也能生成五页 PDF。

**必须纠正的历史设计：** 本阶段曾自行绘制通用建筑示意图。虽然当时明确标为非官方插画，仍不符合用户后续提出的“不要自行添加建筑线条”。Phase 5 已移除该源码的引用与 TikZ 依赖；当前缺失装饰建筑时留空，不再补绘。旧总结保留历史记录，不能据旧描述恢复该方案。

**评价：** 五类页面目标达到；素材处理方式经过纠正。学校素材的公开再分发依据仍未确认。

## 5. Phase 3：视觉模式与配置接口

**总纲要求：** 建立统一配置接口，先实现必要样式与选项，为后续扩展预留结构。

**实际实现：** `theme/huas-config.tex` 通过已有 PGF 键值机制提供六项设置：`style`、`logo`、`footer`、`sectionpage`、`language`、`faculty`。本阶段实现 Academic/Warm，Phase 4 扩展 Cool。后一次配置只覆盖指定项；旧选项与新接口共享状态。

Warm 的暖红背景只用于完整封面、章节和结束页，正文保持浅色。自动章节页由 Beamer 章节钩子生成；完整页面的背景局部生效且不计正文页码。装饰建筑由用户图片路径加载。

**当时验证：** Academic、Warm、英文长标题、简洁/无页脚、重复配置、旧选项和缺图等场景；无效样式会明确报错。

**仍需正确理解：** `language=en` 只切换主题固定标签，不翻译正文、日期和机构；`faculty` 是简短文字，不是学院子主题。自动章节页会被用户自定义 `\AtBeginSection` 替换。完整页面与普通 `\titlepage` 的背景行为不同。

**评价：** 配置目标达到。深色正文、学院标识组合等尚未实现，但总纲明确允许后续扩展，并非当前阻塞项。

## 6. Phase 4：学术内容组件与蓝色版本

**总纲要求：** 引文、文献、图注、表格、代码、内容块、研究流程、文学阅读、文本细读、教学案例与重点页。

**实际实现：** 用 Beamer 原生 `block/alertblock/exampleblock`、列表、图表、数学环境、`verbatim` 和 `thebibliography` 承担常规内容。新增带出处的 `HUASquotation` 和完整重点页命令 `\HUASkeypoint`。研究流程、阅读和教学案例由原生组件组合，未为数量额外制造专有环境。

用户追加蓝色版本，因此本阶段同步实现 Cool：参考本地教学 PDF 的蓝色标题区、深蓝提示栏和浅色内容块，并适配为 16:9。没有复制该 PDF 的正文、个人信息或页面截图。

**当时验证：** Cool 16 页、原 Academic、Warm 组件场景、样式回切及无研究素材的独立源码目录均编译；渲染检查了组件与缺图页面。

**当前限制：** 代码无高亮、行号与自动折行；文献仍为手工条目，不依赖 Biber。超长文字、表格和代码需要作者拆页。`\HUASkeypoint` 是独立 frame，不能放入另一个 frame。

**评价：** 所要求的内容类型已有可用表达方式；没有把“支持某场景”夸大为“已有该场景专用环境”。

## 7. Phase 5：工程化、示例与文档

**总纲要求：** Academic/seminar 示例；README 覆盖编译、最小使用、主题接口、项目状态、素材与非官方声明。

**实际实现：** 新增 Academic 10 页和 Warm seminar 9 页；保留最小示例 5 页和 Cool 16 页。`scripts/build.ps1` 支持四个目标与 all，始终从项目根目录编译两遍，错误即停止，产物集中到 `build/<目标>/`。`examples/local-assets.tex` 条件加载本地素材；普通编译不需要 Python，也不依赖参考仓库。

本阶段还落实用户的三个具体修正：撤销自绘建筑；采用黑体标题、宋体正文；保留校徽原 JPG，默认用只改变透明度的像素去白版，同时保存两份生成式候选供选择。生成式候选有笔画和色泽差异，不能称为原图精确副本。

**当时验证：** 四套共 40 页两遍编译与渲染；无研究素材、从目录外调用构建脚本的 Warm 示例通过；字体检查包含 SimSun/SimHei；去白结果的 RGB 与解码后的原图一致。

**评价：** 示例、构建和 README 目标达到。Phase 5 初期说明对新手仍偏简略，这由 Phase 6 逐模板说明以及本轮零基础手册进一步补足。

## 10. 已解决问题与遗留事项

| 历史问题 | 当前处理 | 剩余边界 |
| --- | --- | --- |
| 早期只有默认封面 | 五类核心视觉页面已实现 | 长内容仍需作者控制 |

| 生成式抠图改了校徽笔画 | 默认使用保留 RGB 的像素去白版；两份候选保留 | JPEG 压缩与淡边无法凭去白恢复 |

| 初版说明偏开发者视角 | 已有逐模板指南；本轮增加从安装开始的手册 | 本轮教学尚未经真人新手完整试用 |

## 12. 总体反思

阶段推进较清晰：先编译最小工程，再拆模块、增加页面、建立配置、扩充内容、补齐示例和文档。原生 Beamer 机制承担主要排版，新增接口数量受实际需要约束。

做得不充分的地方集中在视觉素材判断和使用教学：早期自行补绘建筑后来被用户纠正；生成式校徽抠图不能满足精确保留原图；README 对新手隐藏了终端路径、编译输出、花括号等基础知识。本轮总评明确保留这些问题与纠正过程，手册把基础步骤展开，不把历史不足改写成从未发生。

下一次开发仍需先读总纲与最新总结，以用户最新要求和当前源码为准。历史总结中旧路径、已撤销的建筑回退及早期默认字体不能直接作为现行使用说明。优先验证真实报告的修改反馈，再决定是否增加接口。
